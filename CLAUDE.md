# batterie — Assembled Plugin Marketplace

This repo is the **assembled marketplace mirror** for the Batterie de Savoir plugin suite. `plugins/` holds vendored copies of each plugin, assembled from the standalone source repos. Since the 2026-06-10 cutover (`bds-bajibo`) it is the single marketplace, serving the **public CLI** (`claude plugin marketplace add spm1001/batterie`) and **personal Desktop** installs (Customize → Add marketplace — both accept a public repo).

**The repo is deliberately PUBLIC** (decided 2026-06-20, `bds-kanuve`). The cost, accepted knowingly: the claude.ai **org/Teams Directory is NOT a surface for this repo** — org marketplaces require a *private or internal* repo (Anthropic policy; "internal" needs a GitHub Org/Enterprise, which `spm1001` isn't). The org marketplace registration was removed. **Do NOT re-add it** (it errors on every sync) and **do NOT flip the repo private to "fix Teams"** — that breaks the CLI/personal path everyone actually uses. Family-scale users get the Teams Directory via a **separate private repo** carrying the `batterie-home` output (see "Two outputs, one pipeline" below; tracked in batterie-de-savoir's `bds-niluga`).

Not to be confused with **batterie-de-savoir** — the two are a **source/artifact pair**: that one is where the suite is *authored* (the docs umbrella — brigade.toml, Jekyll site — and the source of the suite-level `batterie` plugin); this one is what clients consume. Don't retire bds in a tidy-up: assessed 2026-06-11 — it sources the suite plugin, holds the brigade registry, serves the live Pages docs site, and the tool repos' READMEs link into it.

## The iron rule

**Never hand-edit `plugins/`.** Everything under it is generated by `assemble.sh` from the source repos. To change a plugin: change its source repo, then either wait for the daily workflow or run `./assemble.sh` locally and commit. A hand-edit here is drift waiting to be clobbered.

**Prefer the bot for publishing.** Local assemble runs read the source repos' *working trees* — uncommitted or untracked files get vendored and shipped. (A never-committed tafelmusik `.mcp.json` pointing at `ws://hezza:3456` reached clients this way; the runner's clean clones removed it on 2026-06-04.) Local runs are for preview; let the daily workflow do the committing where possible.

## Two outputs, one pipeline (bds-mumise)

The same `assemble.sh` run emits **two marketplaces**:

- **Public `batterie`** — this repo, as ever (committed + pushed by the workflow).
- **Private `batterie-home`** — a local `dist/batterie-home/` tree (gitignored): **mise only**, transformed to **mise-home** by `transforms/make-mise-flavour.sh` (identity strings rewritten, planetmodha OAuth client swapped in, a guard failing loud on any leftover ITV-identifying string). It derives from the **just-vendored public mise**, so both marketplaces carry identical runtime bytes and the same suite version — drift is structurally impossible. Emitted only when `MISE_HOME_CRED` points at the planetmodha `credentials.json`. **mise-home only, deliberately** (`bds-rikeno`, 2026-07-13): a whole-suite mirror was built then reversed — each CLI-backed plugin's `ensure-*.sh` SessionStart hook auto-installs its CLI + injects its rules shard, so mirroring drags per-session noise onto a family machine for tools nobody asked for. batterie-home's only reason to exist is the planetmodha cred; everything else is public. Instead, `assemble.sh` ships a **family stub** with the flavour, telling a family Claude the rest is public + how to add it — don't remove it, and don't re-mirror the suite. It lives in an **on-demand skill** (`plugins/mise-home/skills/batterie-suite/`), *not* in the instruction shard: `rules/*.md` loads unconditionally, so an append there put twenty lines of family install guidance into every session on every machine carrying mise-home — Sameer's ITV work sessions included (moved 2026-07-26). The skill keeps what made always-on attractive — its description sits in the picker every session, so a family Claude still finds it unprompted — for one line of standing context instead of twenty. A ratchet in `assemble.sh` fails the build if the guide reappears in `instructions.md`. **In CI this is fully wired** (`bds-susugu`): the workflow materialises the cred from the `MISE_HOME_CRED_JSON` secret and pushes the output to [`spm1001/batterie-home`](https://github.com/spm1001/batterie-home) over a write deploy key (`BATTERIE_HOME_DEPLOY_KEY` secret) — one run, both marketplaces. Secrets absent → private half skips gracefully, public unaffected — but the skip can't stay silent: the `batterie-home-publish` deadman (below) starves and emails within ~31h (`bds-bidasi`).

Every vendored plugin (both outputs) is stamped with the **one suite version** — the `batterie` plugin's own number, sourced from batterie-de-savoir (`bds-suwoho`). Source repos' own plugin.json versions are local-dev/CLI-footnote only.

**Manual fallback for the private output** (CI does this every run; use only if Actions is down):

```
MISE_HOME_CRED=<path-to-planetmodha-credentials.json> ./assemble.sh
rsync -a --delete --exclude .git dist/batterie-home/ ../batterie-home/   # a clone of spm1001/batterie-home
git -C ../batterie-home add -A && git -C ../batterie-home commit -m "batterie-home <suite-version> — reassemble" && git -C ../batterie-home push
```

The cred lives outside git (hezza: `~/scratch/mise-flavour/mise-home/credentials.json`; it's also vendored inside the private repo itself at `plugins/mise-home/credentials.json`, so a checkout of that repo can seed the env var). Rotating the deploy key: mint a new keypair, `gh api repos/spm1001/batterie-home/keys` the public half (write), `gh secret set BATTERIE_HOME_DEPLOY_KEY -R spm1001/batterie` the private half, delete the old key.

## Why commits here matter — the update bus

**Clients re-resolve a marketplace's plugins only when the marketplace repo itself gets a new commit** (confirmed by probe, 2026-06-04). A version bump in a source repo is invisible to CLI/Desktop clients until a commit lands *here*. The assemble workflow's daily commit stream is therefore the suite's update bus — propagation latency to every surface equals its cadence.

## The pipeline

`.github/workflows/assemble.yml` (daily 07:00 UTC + manual dispatch) clones the source repos, runs `assemble.sh`, lints, and **pushes straight to main** — no PR. Each commit body lists every plugin's version and source SHA (forensics: any "why is X stale?" is answerable from `git log` alone).

A **red run goes red loudly** — GitHub emails on scheduled-run failures — and since 2026-07-07 the run is also backstopped by **Healthchecks deadman checks** (see Drift guards below), which catch what failure-emails can't: runs that stop happening at all, and the green-but-skipped private publish. A green run *means* a fresh check happened and main reflects the sources.

**Drift guards** (added 2026-06-04, after the structural worry-pass):

- **Heartbeat** — GitHub auto-disables scheduled workflows after ~60 days of repo inactivity; a long drift-free stretch would silently kill the schedule. If the last commit is >25 days old, the no-change path commits a dated `.assemble-heartbeat` instead of exiting quietly.
- **Single clone list** — the workflow derives its clone list from assemble.sh's PLUGINS mapping; a repo mapped there cannot be silently un-cloned (the tafelmusik failure mode).
- **Manifest invariant** — a marketplace.json entry whose `./plugins/X` has no vendored plugin.json fails the run (the gueridon / batterie-0.1.6 husk failure mode). The reverse (vendored but unlisted) only warns: publishing is a human decision.
- **Version ratchet** — a plugin whose vendored content changed without the **suite** version bumping is **quarantined, not fatal** (2026-06-17, `bds-pujaki`; suite-level since the single-version cutover — it compares content against the last-published *suite* version, because every vendored plugin.json is stamped to that one number): the laggard's vendored dir is reverted to its last-published version (the marketplace stays consistent — last-good, not stale-new-content) and the *healthy* plugins still publish that run; a final workflow step then fails the run **red**, naming the laggard, so a missed bump can't hide behind green. One repo's missed bump no longer wedges the whole bus. This is deliberately *softer* than the manifest/husk guards above — those are content **corruption** and stay hard-fail (never publish a husk); a version lag is recoverable. Without the ratchet at all, clients would see "no update available" over silently drifted content. Local escape hatch: `ASSEMBLE_NO_RATCHET=1`.
- **Deadman alerting** (2026-07-07, `bds-bidasi`) — two Healthchecks.io checks (period 1d + grace 6h, email on silence), pinged by final `if: success()` workflow steps: `batterie-assemble` (any red run — quarantine included — or a dead/disabled schedule starves it) and `batterie-home-publish` (fed only when the private-push step reports `state=pushed|current`, so a secret-absent silent skip alarms even though the run stays green). Ping URLs are capability tokens in Actions secrets (`ASSEMBLE_HC_URL`, `BATTERIE_HOME_HC_URL`); a missing secret produces a `::warning::` in the run log, and both pings were verified against a real run + a live `/fail` → email → recovery test. Complements the heartbeat above: the heartbeat prevents one *cause* of schedule death, the deadman catches *every* cause of silence.

History that shaped this design (May 2026 drift, diagnosed in `~/notes/raw/2026-05-31-mise-update-bug-vendor-drift.md`, post-mortem 2026-06-04):

- The previous PR-based flow needed a weekly human merge that never happened — mise 0.7.3 sat in an unmerged PR for 17 days while every surface served 0.7.2.
- `git diff --quiet` change detection missed untracked (new) files — a week of purely-new-file drift produced no PR at all. Now `git status --porcelain`.
- The suite-level `batterie` plugin was once declared at `./` with a root plugin.json but no vendored content — org members installed a version string over nothing. It now lives in `plugins/batterie/` like its siblings.

## Troubleshooting "Desktop shows a stale version"

1. **Did the suite version bump?** Post-cutover, a source repo's own `plugin.json` version is local-dev-only — publishing is gated on the **suite** version (batterie-de-savoir's `.claude-plugin/plugin.json`), which the assembler stamps onto every plugin. Check the vendored `plugins/<name>/.claude-plugin/plugin.json` here on `main`: all should read the current suite number. (A source change with no suite bump is *quarantined* — see the ratchet above.)
2. **Did an assemble commit land here since?** `git log --oneline -5` — the commit body shows per-plugin versions/SHAs.
3. **Did the workflow run and go green?** `gh run list --workflow=assemble.yml` — but remember green only means *the run* worked; step 2 is the product check.
4. **Client-side:** Desktop re-syncs on marketplace-repo commits; CC CLI on `claude plugin marketplace update` (or autoUpdate).
